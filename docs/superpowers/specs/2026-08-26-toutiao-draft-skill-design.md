# 今日头条安全草稿 Skill 设计

## 目标

把现有 `toutiaohao-mcp-server` 改造成一个可由 Codex 自动发现和调用的本地 Skill，用于将带正文插图和封面的文章保存到今日头条草稿箱。默认运行路径不得发布文章；保存操作必须回查草稿箱并确认目标草稿存在后才返回成功。

## 范围

本期包含：

- 图文文章草稿保存，支持 Markdown 本地插图和独立封面。
- 浏览器登录态初始化、健康检查、服务构建和 MCP 启动脚本。
- 本机网络隔离、发布保险、Cookie 隔离和日志脱敏。
- 草稿保存后的标题回查与有限重试。
- 本地 Skill 的说明、触发条件和故障处理指引。

本期不包含：

- 自动点击最终发布。
- 定时发布、评论回复、内容删除或批量运营。
- 将 HTTP 服务暴露到局域网或公网。
- 绕过验证码、风控或今日头条平台限制。

## 方案选择

采用“自包含本地 Skill + 固定版本 Go 服务源码 + 安全包装脚本”。Skill 内保留经过审计的运行源码和确定性的构建、登录、诊断脚本，不依赖当前工作目录中的临时克隆。相比只包装现有目录，这种方式不受目录移动影响；相比重写 Playwright 发布器，它复用已经验证的 go-rod 编辑器和图片上传逻辑。

## 目录与组件

最终 Skill 名称为 `toutiao-draft-publisher`，安装到 Codex 本地 Skills 目录。结构如下：

```text
toutiao-draft-publisher/
├── SKILL.md
├── agents/openai.yaml
├── scripts/
│   ├── build.sh
│   ├── doctor.sh
│   ├── login.sh
│   └── run-mcp.sh
├── runtime/
│   └── toutiaohao-server/     # 固定版本、经过安全改造的 Go 源码
└── references/
    └── troubleshooting.md
```

- `SKILL.md`：定义触发场景、授权边界、草稿工作流和必须停止的条件。
- `build.sh`：在 Skill 内构建服务端二进制，不下载或执行不固定版本的远程代码。
- `doctor.sh`：只读检查 Go、Chrome、二进制和 Cookie 文件状态，不输出 Cookie 内容。
- `login.sh`：以可见 Chrome 启动一次登录流程，将 Cookie 保存到用户数据目录。
- `run-mcp.sh`：以 stdio 模式启动 MCP；不额外启动 REST 服务。
- `runtime/toutiaohao-server`：保留原项目的正文插图、封面上传和草稿管理能力，并加入安全限制。
- `troubleshooting.md`：记录登录失效、图片上传失败、草稿回查超时等条件的处理方式。

Cookie 与运行日志不存放在 Skill 目录或 Git 仓库中。默认状态目录使用操作系统用户数据目录，并允许通过 `TOUTIAOHAO_COOKIES_PATH` 显式覆盖。

## 安全模型

### 网络边界

- stdio 模式只运行 MCP stdio，不启动后台 REST 服务。
- 显式启动 HTTP 模式时仅绑定 `127.0.0.1`。
- CORS 不允许通配符来源；本地 HTTP 模式只接受配置的本机来源。
- HTTP 写操作要求 Bearer Token；未配置 Token 时拒绝启动 HTTP 写接口。

### 发布边界

- 新增独立的 `save_article_draft` MCP 工具，作为 Skill 的唯一默认写入入口。
- `publish_article`、`publish_micro_post` 等正式发布入口默认拒绝执行。
- 正式发布只有同时满足环境变量 `TOUTIAO_ALLOW_PUBLISH=1` 和请求参数 `confirm_publish=true` 时才可继续；Skill 本身不得代替用户设置这两个条件。
- 用户仅授权“保存草稿”时，任何发布参数缺失、冲突或平台页面状态不明确都必须停止，不得降级成发布。

### 凭证与日志

- Cookie 文件权限设为仅当前用户可读写。
- 日志不得打印 Cookie、Authorization、请求头或完整账号信息。
- `.gitignore` 必须覆盖 Cookie、构建产物、临时图片和错误截图。

## 草稿保存数据流

1. 调用方提供标题、正文 Markdown、正文插图路径和可选封面路径。
2. 服务在启动浏览器前校验标题长度、正文非空、图片存在且类型受支持。
3. 服务加载本地 Cookie；失效时停止并要求执行登录脚本。
4. 浏览器打开图文编辑页，写入标题和正文，在 Markdown 指定位置上传插图，并设置封面。
5. 服务不点击“发布”或任何等价确认按钮，等待平台自动保存提示或稳定期。
6. 服务调用草稿列表读取能力，按规范化标题查找新草稿；采用有限次数、递增间隔的重试。
7. 回查命中后返回草稿 ID、标题和草稿状态；超时则返回失败，并明确提示用户人工检查草稿箱，不宣称保存成功。

为避免误匹配，回查以完整标题为主键，并以调用开始时间过滤明显更早的同名草稿。若平台列表无法提供可靠时间，则返回“存在同名草稿但无法唯一确认”，要求人工确认。

## 错误处理

- 登录失效：停止操作并提示运行 `login.sh`。
- 本地图片不存在或上传失败：停止，不继续保存缺图草稿。
- 页面出现发布确认弹窗：立即停止并保存脱敏错误截图，绝不点击确认。
- 草稿回查超时：返回失败和人工检查路径，保留平台可能已自动保存的草稿。
- 平台 DOM 或接口变化：保存诊断信息，但不记录正文全文、Cookie 或敏感请求头。

所有自动重试均有上限，不重复创建新编辑页，避免生成多份草稿。

## 测试策略

### 单元测试

- stdio 模式不调用 HTTP 后台启动函数。
- HTTP 地址固定为 `127.0.0.1:<port>`。
- 未满足双重解锁时，所有正式发布路径返回拒绝错误。
- `save_article_draft` 强制设置草稿模式，忽略任何发布时间。
- 草稿回查在命中、超时、同名歧义和临时接口失败时返回正确结果。
- Cookie 文件保存后权限为 `0600`。

### 脚本测试

- `build.sh` 能完成构建并输出固定位置的二进制。
- `doctor.sh` 在依赖齐全和缺少依赖时返回可读结果，且输出不含 Cookie。
- `run-mcp.sh` 启动后没有监听 TCP 端口。
- Skill 使用官方验证脚本通过结构和 frontmatter 检查。

### 账号集成验证

在用户已登录并明确授权保存草稿后，使用一篇带唯一测试标题和本地图片的文章执行一次保存：

- 编辑器成功写入标题、正文、插图和封面。
- 未发生最终发布。
- 草稿列表能够回查到相同标题并返回草稿 ID。

测试草稿属于用户账号数据，不自动删除；是否删除必须另行取得用户授权。

## 完成标准

- 全部单元测试、脚本测试、Go 构建和 Skill 校验通过。
- stdio 进程没有打开监听端口。
- 未显式双重解锁时，正式发布测试均被拒绝。
- 使用已登录账号保存一篇测试草稿并成功回查，且用户主页没有新增已发布文章。
- 本地 Skill 可被 Codex 发现，其默认指令只引导保存草稿。
